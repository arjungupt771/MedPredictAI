## ✨ Overview

Most ML projects stop at `Dataset → Model → Accuracy`. MedPredict AI treats the model as one component of a system:

```
Symptoms → Validation → Red-Flag Safety Gate → Calibrated ML Model → Uncertainty
        → SHAP Explainability → FastAPI → Streamlit → PDF Report
```

## 🚀 Features

| Feature | Description |
|---|---|
| 🤖 **Model comparison** | Random Forest vs XGBoost, best model selected by weighted F1 |
| 🎯 **Calibrated confidence** | Sigmoid-calibrated probabilities, exposed with margin and uncertainty |
| 🏆 **Top-3 predictions** | Differential diagnosis with calibrated scores and specialist suggestions |
| 🔍 **SHAP explainability** | Per-symptom impact scores with direction and strength (not percentages) |
| ✅ **Input validation** | Normalization, de-duplication, unknown-symptom rejection |
| 🧭 **Insufficient-information state** | Refuses to predict from too little input instead of guessing |
| 🚨 **Red-flag safety layer** | Deterministic rules run *before* the ML model and return an urgent-care message |
| 📄 **PDF reports** | Downloadable patient report including confidence and SHAP factors |
| 🗣️ **Plain-language summary (optional)** | LLM rephrases the ML result against a fixed knowledge base; template fallback if no API key |
| 🧪 **Tests + CI** | pytest suite, GitHub Actions running tests and Docker builds |
| 🧾 **Model metadata + experiments** | Versioned model info, dataset hash, JSON experiment logs |
| 🐳 **Docker** | Non-root containers with health checks |

## 📊 Model Performance

Evaluated on a **synthetic** dataset (2,400 samples, 20 diseases, 57 symptoms, 120 samples per disease).

| Model | Accuracy | Weighted F1 | Macro F1 |
|---|---|---|---|
| Random Forest (selected) | **94.38%** | **94.36%** | **94.36%** |
| XGBoost | 93.54% | 93.53% | 93.53% |

**5-fold stratified cross-validation (Random Forest):** 94.33% ± 0.90% accuracy.

### ⚠️ Limitations (please read)

- The dataset is **synthetically generated** from predefined disease-symptom rules, so these metrics mostly measure how well the model learns those rules, **not real-world clinical performance**.
- To evaluate on external data, place a CSV with the same symptom columns plus a `disease` column at `dataset/external_test.csv`; `train_model.py` will evaluate on it automatically and report the result separately.
- Calibrated probabilities are model probabilities, **not diagnostic certainty**.
- SHAP explains the underlying tree ensemble; confidence comes from its calibrated wrapper, so rankings can occasionally differ slightly.
- Not a medical device. See disclaimer below.

## ⚡ Quick Start

```bash
pip install -r requirements.txt

# 1. Generate dataset and train (writes models/, experiments/)
python dataset/generate_dataset.py
python notebooks/train_model.py

# 2. Run tests
pytest tests/ -v

# 3. Backend
cd backend
uvicorn app:app --reload        # http://localhost:8000/docs

# 4. Frontend (new terminal)
cd frontend
streamlit run app.py            # http://localhost:8501
```

Set `API_URL` if the backend is not on `http://localhost:8000`. Optionally set `ANTHROPIC_API_KEY` to enable the LLM plain-language summary; without it the app uses a template fallback.

### Docker
```bash
cd docker
docker-compose up --build
```

### Example: Predict
```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"symptoms": ["fever", "cough", "headache"]}'
```

Response shape (values illustrative):
```json
{
  "top_prediction": {"disease": "Influenza", "confidence": 0.31, "confidence_pct": 31.0, "doctor": "General Physician"},
  "top3": [ ... ],
  "margin": 0.08,
  "uncertainty": 0.69,
  "low_confidence": true,
  "matched_symptoms": ["fever", "cough", "headache"],
  "unrecognized_symptoms": [],
  "confidence_note": "Confidence is a calibrated model probability, not diagnostic certainty."
}
```

Other possible outcomes: `422` for invalid input (no recognized symptoms), `{"insufficient_information": true, ...}` when too few symptoms are given, and `{"red_flag": true, ...}` when a safety rule fires (no ML prediction is returned).

## 🧠 Design Decisions

- **Safety before ML:** red-flag rules are deterministic and run before inference, so safety-critical behavior never depends on a probabilistic model.
- **Abstain instead of guess:** the pipeline returns "insufficient information" rather than forcing a prediction.
- **Calibration:** raw Random Forest scores are not probabilities; a sigmoid-calibrated wrapper provides the confidence shown to users.
- **Honest explainability:** SHAP values are shown as signed impact scores, not percentages.
- **Real API boundary:** the Streamlit app talks to FastAPI over HTTP rather than importing backend code.

## UCI Heart Disease Benchmark

MedPredict AI includes an independent benchmark using the UCI Heart Disease dataset.

The benchmark is deliberately separated from the primary 20-disease symptom-classification system because the two models solve different prediction problems.

### Tasks

| System                | Input                 | Prediction                          |
| --------------------- | --------------------- | ----------------------------------- |
| Primary MedPredict AI | Symptoms              | Multi-class disease classification  |
| UCI Benchmark         | Clinical measurements | Binary heart-disease classification |

### Benchmark methodology

The UCI benchmark evaluates three model families:

* Logistic Regression
* Random Forest
* XGBoost

Model selection is performed using stratified 5-fold cross-validation on the available dataset. The held-out test split is reserved for final evaluation.

The selected model is then probability-calibrated using `CalibratedClassifierCV`.

Reported metrics include:

* Accuracy
* Precision
* Recall
* F1
* ROC-AUC
* Brier score
* 5-fold cross-validation performance

### Results

| Dataset       | Selected Model      |      CV ROC-AUC | Final Test ROC-AUC | Test F1 |
| ------------- | ------------------- | --------------: | -----------------: | ------: |
| Cleveland     | Logistic Regression | 0.9065 ± 0.0197 |             0.9589 |  0.8667 |
| Hungarian     | Logistic Regression | 0.9055 ± 0.0404 |             0.9361 |  0.7027 |
| Switzerland   | Random Forest       | 0.8784 ± 0.1382 |             0.5435 |  0.9583 |
| VA Long Beach | Random Forest       | 0.6747 ± 0.0724 |             0.7267 |  0.8955 |

### Interpretation

The benchmark demonstrates substantial variation between cohorts.

The Cleveland and Hungarian datasets produce relatively consistent cross-validation ROC-AUC values, while the Switzerland dataset exhibits high variability across folds. The Switzerland cohort is particularly imbalanced, with only eight samples in the negative class, so accuracy and F1 should not be interpreted independently of ROC-AUC and cross-validation variability.

The VA Long Beach dataset also contains substantial missingness, including 198 missing values for the `ca` feature. The preprocessing pipeline retains feature structure consistently across cross-validation folds and handles missing values within the model pipeline.

These results demonstrate why evaluating an ML system across multiple datasets and using multiple metrics is more informative than reporting a single accuracy value.

### Reproducibility

Run the benchmark with:

```bash
python -m benchmarks.uci_heart_disease.train --dataset cleveland
python -m benchmarks.uci_heart_disease.train --dataset hungarian
python -m benchmarks.uci_heart_disease.train --dataset switzerland
python -m benchmarks.uci_heart_disease.train --dataset va
```

Then generate the consolidated benchmark:

```bash
python -m benchmarks.uci_heart_disease.compare
```

Results are stored under:

```text
experiments/uci_heart_disease/
```
